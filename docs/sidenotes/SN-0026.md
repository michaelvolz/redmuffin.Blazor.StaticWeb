# OpenCode Permissions Plan Requirements

## Core Requirements

1. **Minimal Configuration**
   - Configure as few permissions as possible
   - Too many rules make errors invisible to us
   - Default to allow wherever safe

2. **Smooth Workflow**
   - cc-safety plugin handles command-level dangers
   - Custom push blocker for git safety
   - Both can be configured further if needed

3. **Security Protection**
   - Supply chain attack prevention
   - Prompt injection protection
   - Vital system folders protected
   - Cross-platform: Windows 11 + Omarchy (Linux)

4. **Ask for Important + Dangerous**
   - Model needs to do important tasks sometimes
   - But dangerous for system = ask
   - Balance between useful and protective

5. **System Admin Use Case**
   - Full blocking not an option
   - Only security-related stuff blocked
   - Common tasks needed:
     - Global npm installs
     - OpenCode global settings
     - Winget package management
     - PowerShell profile/script changes

6. **Balance Principle**
   - Vital files secured vs system used properly
   - When in doubt = ask
   - User is the arbiter of decision
   - OpenCode does "ask" well

## What We Need to Decide

- What permissions to KEEP (deny/ask)
- What to REMOVE (let defaults handle)
- What vital folders/files to PROTECT
- How to handle cross-platform (Windows 11 vs Omarchy)
- When to use deny vs ask

## Open Questions

- Are there conflicts between requirements?
- Did we miss any important requirements?
- Should we brainstorm before planning?

# CRITICAL: cc-safety-net Scope vs Permissions Gap

## What cc-safety-net HANDLES (bash commands only)

The plugin is a PreToolUse hook that intercepts Bash commands. It BLOCKS:

- Git destructive: git reset --hard, git clean -f, git checkout --, git push --force, git branch -D, git stash drop
- Filesystem destructive: rm -rf (outside cwd, root/home), xargs rm -rf, find -delete
- Shell wrappers: bash -c '...', sh -lc '...'
- Interpreter one-liners: python -c, node -e, ruby -e with destructive commands

## What cc-safety-net CANNOT Handle

The plugin ONLY sees bash commands. It CANNOT block:

- **READ tool** accessing sensitive files (e.g., read ~/.ssh/id_rsa)
- **EDIT/WRITE tool** modifying files
- **GLOB tool** finding sensitive file patterns
- **GREP tool** searching sensitive content
- **TASK tool** launching subagents
- **SKILL tool** loading skills
- external_directory (workspace escape)
- doom_loop detection

## THE SECURITY GAP

A model can bypass cc-safety-net by using:

1. read tool on ~/.ssh/id_rsa, ~/.env, secrets.json
2. glob ~/.config/\**/*secrets\*
3. grep -r "API_KEY" ~/\*\*

Plugin doesn't intercept these — permissions MUST handle them.
