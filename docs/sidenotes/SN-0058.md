# Extra pipeline zoo (not for now)

**Disposition:** not used for modularization. LoggingBehavior is enough. Possible future task only.

**What it is:** stacking more `IPipelineBehavior`s (authorization, caching, retry, idempotency, etc.) on every Mediator request “because RiverBooks does pipelines.”

**Why parked:** pipelines earn their keep as **shared cross-module** policy. Premature zoo adds indirection and debug cost with one thin module template and one IO module. Prefer handler-local logic until pain is repeated.

**Production impact:** usually small code size; main cost is complexity and ordering bugs between behaviors.

**Revisit when:** the same cross-cutting rule is copy-pasted across multiple module handlers and a behavior is the simpler fix. One behavior at a time, with a named need.
