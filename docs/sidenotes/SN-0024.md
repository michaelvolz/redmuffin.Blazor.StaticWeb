## Problem

The production site (redmuffin.net) shows verbose console logging output from Blazor components and HTTP client diagnostics. This includes:

- Component lifecycle messages ("OnInitialized called", "OnParametersSetAsync called", etc.)
- HTTP client diagnostic messages ("Start processing HTTP request", "Sending HTTP request", etc.)

## Root Cause

- `Program.cs` has no logging configuration, so it defaults to `LogLevel.Information` which outputs to browser console
- Unlike server-side ASP.NET Core, there's no automatic suppression of logging in Release mode for Blazor WASM

## Solution

1. **Add logging configuration to Program.cs** to set minimum level to `LogLevel.Warning` in production (only show errors/warnings)
2. **Add a URL flag to enable logging on-the-fly** for debugging any production page

The URL flag should work like:

- `https://redmuffin.net/?debug=true` - enables all logging (Information level)
- Or query parameter like `?logging=enabled`

This allows debugging production issues without needing to redeploy or change build configurations.
