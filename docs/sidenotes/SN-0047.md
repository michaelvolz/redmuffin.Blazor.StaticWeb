Two image validators coexist: ImageValidationCacheService (Core, 153L,
placeholder-based) and SimpleImageValidationService (ArticlesPage, 309L,
localStorage + HTTP HEAD). Both are registered in DI. The user flagged this
as needing caution — the two services may be genuinely different strategies
rather than a wrong abstraction. If they ARE different strategies, they need
clear, distinct names that reflect their strategy. If one is redundant,
consolidate behind a single IImageValidator interface.

Needs thorough caller analysis and a grill-with-docs decision before any
code change.
