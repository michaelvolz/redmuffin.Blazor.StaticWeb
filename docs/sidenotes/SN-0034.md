title: Research command-line switch to temporarily disable TreatWarningsAsErrors during quality gate tool runs
status: dismissed
dismissed-reason: Already done. The only gate that spawns dotnet build (mutation) passes `-p:TreatWarningsAsErrors=false` to the fixture project. The other four gates read source via Roslyn and never invoke dotnet build on the target. Both solutions are 0/0 anyway.
---

Investigate whether we can re-enable warnings-as-errors globally for both solutions
but have the quality tools temporarily disable it when they spawn `dotnet build` or
`dotnet test` processes. The tools already pass `-p:` flags to dotnet (e.g.,
`-p:TreatWarningsAsErrors=false` in MutationRunner.cs). We should check if every
tool invocation that spawns a dotnet subprocess can add this flag automatically.
This way normal coding sessions stay protected with TreatWarningsAsErrors, but
quality gate operations (CRAP coverage generation, mutation testing builds) can
focus on CRAP scores without being blocked by analyzer warnings. The warnings
would then be fixed as a separate, dedicated pass.
