# Move Azure Functions into Modules (not for now — permanent hard no)

**Disposition:** not a future modularization task in the positive sense. Captured so the idea is **closed**: do not “extract” Functions for RiverBooks.

**What people mean:** relocate Azure Functions triggers, workers, or Api-only types from `src/redmuffin.Blazor.StaticWeb.Api/` into `Modules/` under the modular-monolith banner.

**Why rejected:** Api is a **separate deployment unit** (SWA Functions). Client modules may HTTP-call `/api/...` only. Dual-consumed DTOs go in Common when deliberate. ADR 0013 + AGENTS hard constraint.

**Production impact:** wrong packaging and deploy story; not a size optimization.

**Revisit when:** never as modularization. Only if platform or product ownership of Functions changes under a new ADR — not under RiverBooks cleanup.
