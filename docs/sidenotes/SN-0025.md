**Root cause:** Instruction conflict between `rm-reliable-dotnet-coder` persona (sequential, "never guess") and CE skills (`<parallel_tasks>`).

**Solution:** Added "Parallel Task Execution" section to both:

- `.opencode/agents/rm-reliable-dotnet-coder.md`
- `.opencode/agents/rm-daily-dotnet-coder.md`

The instructions now explicitly state that parallel dispatch takes priority over sequential reasoning protocol.

We need to find a way that calls to analyzers, reviewers, agents, or skills marked as parallel_tasks are ALWAYS executed as such and not sequentially, which makes the tools almost useless for the user.

Specific issue: When skills or agents have parallel tool calls defined (e.g., multiple reviewer agents dispatched in parallel), they get executed one after another instead of in parallel. This defeats the purpose of parallel execution (e.g., running multiple reviewers at once for speed) and makes them slow/nearly useless.

We need either:

1. Fix at the OpenCode agent/task dispatch level (intercept and fix execution order)
2. Document/workaround in skill definitions
3. Raise with OpenCode maintainers as a bug
