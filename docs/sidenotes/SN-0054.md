# Validator / validation pipeline (not for now)

**Disposition:** not used for modularization. Possible future task only.

**What it is:** a Mediator `IPipelineBehavior` that validates every `IRequest` (FluentValidation-style or DataAnnotations) before the handler runs.

**Why parked:** Mediator surface is still tiny (one proven query pattern on ApiHealth). Ad-hoc validation already exists where needed (e.g. attributes in Common). A global validation pipeline is complexity without shared request rules across modules.

**Production impact:** small if added later (a bit of runtime code); not a major WASM size driver compared to OTEL.

**Revisit when:** several modules share the same request-validation shape and copy-paste validation becomes painful. Until then: ignore.
