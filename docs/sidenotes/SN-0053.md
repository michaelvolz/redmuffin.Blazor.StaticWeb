# OTEL Mediator pipeline (not for now)

**Disposition:** not part of RiverBooks modularization. Possible future observability task only.

**What it is:** an `IPipelineBehavior` (and client/server OTEL packages) that traces or metrics every `IMediator.Send`, beyond today’s `LoggingBehavior`.

**Why parked:** modularization does not need distributed tracing. Full OpenTelemetry on Blazor WASM is a product decision (exporter, sampling, privacy) and can grow the **client download** if packages are referenced by the WASM project.

**Production impact:** **can bloat** published WASM if OTEL SDKs land in the host graph. Keep any trial behind a size budget and measure before/after publish.

**Revisit when:** there is a dedicated observability PRD with acceptance on bundle size and what to measure. Not a dependency of finishing modules.
